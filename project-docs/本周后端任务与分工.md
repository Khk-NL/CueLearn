## 开工前对齐的决定

本项目已使用 PocketBase 管理账号与学习数据；课程 PDF 要求 Python API、SQLite SQL、`?` 与 `LEFT JOIN`。需要先明确课程服务与现有 PocketBase 的职责、数据来源和调用方式，再由各人依照同一契约实现。现有源码迁入 `app/desktop/` 只完成组织调整，没有把 TypeScript 业务自动转换为 Python API。

由梁组织首次会议，肖整理接口边界与需要向教师确认的问题，全组确认课程是否接受 PocketBase 等价实现，还是必须提交 Python/SQLite 改造。若必须使用 SQLite，可讨论将课程服务限定为匿名学习事件与分析数据、PocketBase 继续承载现有账号与学习记录；此方案尚待确认，不能写成已确定架构。还须明确用户标识映射、事件写入时机、重复事件及失败的处理方式，避免两套状态相互矛盾。

在边界确认前，可以完成模型草案、接口例子、事件采集点清单与测试场景设计；数据库迁移与数据同步方案依照确认结果实施。

1. **第 1 天需求对齐会**：梁组织会议，肖记录接口与技术边界；全组确认最小流程“完成一次语境复习 → 保存学习事件 → 查看统计”，对齐字段、接口、时长含义与数据来源。

会议记录包含日期、参与人、当前分支及 PR、实际完成证据、阻碍和下一步负责人。正式截止时间以教师通知为准。

## 分支与提交

本次目录调整直接集成至 `main`。组员开始业务实现时先更新本地 `main`，再分别创建 `test/course-api`、`feat/course-models`、`feat/course-storage`、`feat/course-event-capture`、`feat/course-api` 等分支，向 `main` 提 PR，由另一位组员核对后合并。已有分支先合并目录调整，再在 `app/desktop/` 下编辑，不重复创建 `src/`。

提交使用 `feat:`、`fix:`、`test:`、`docs:` 等前缀；不提交 `learn.db`、PocketBase 数据、视频、密钥或本机环境。每个 PR 写清改动、验证命令、实际结果与尚未验证事项。课程验收以模型、API、实际数据和测试结果为依据，仅有骨架不能算完成作业。
