# CueLearn 用户画像与用户故事

**课程作业草稿｜2026 年 10 月 14 日**  
**小组成员：**梁恩华、郑天齐、李章韬、肖俊辉  
**产品主题：**面向个人视频学习的桌面应用

本文承接 CueLearn 的开发方案与现有原型。用户把本机带字幕的视频作为学习资料，在观看时收藏带原句和时间点的生词，按间隔复习；也可将视频加入笔记本，围绕所选字幕提问、做测验，并点击出处回到视频核对。以下画像是供小组讨论的**假设画像**，不是访谈统计结论。故事中的“现有”仅表示代码已提供相应入口，仍须按验收标准进行实机验证；“迭代”表示尚未实现。

## 1 用户画像

### 1.1 画像一 林悦 以外语视频学习的本科生

| 项目 | 内容 |
| --- | --- |
| 基础信息 | 林悦，20 岁，英语专业本科二年级，常住杭州，在宿舍和图书馆学习。 |
| 教育与技术水平 | 熟悉播放器、字幕文件和常用学习软件；能自行选择视频与字幕，不愿配置复杂服务。 |
| 兴趣与生活方式 | 看英语访谈和纪录片；每天分段学习 20 至 40 分钟，通勤时复习。 |
| 主要需求 | 从正在看的视频中保存生词的原句和原声，第二天能找到到期卡片并回看当时的片段。 |
| 次要需求 | 导入已有本地词表；清楚看到当天待复习数量和进度。 |
| 核心痛点 | 普通单词卡脱离听到它的情境；手工复制字幕、视频名称和时间点容易中断观看；重复收藏造成多张相同卡片。 |
| 代表场景 | 看访谈时遇到一个新词，暂停查词并收藏；次日听原句回忆词义，忘记时跳回访谈片段。 |

**需求推导：**收藏动作要保留句子、视频标识和字幕时间点；复习卡应先呈现语境，再揭示词义；同一词重复出现时增加语境，而不重复建词。

### 1.2 画像二 周航 通过课程视频学习的研究生

| 项目 | 内容 |
| --- | --- |
| 基础信息 | 周航，24 岁，计算机专业硕士一年级，常住南京。 |
| 教育与技术水平 | 能管理本地课程视频和字幕，熟悉 AI 问答，但会核对模型给出的结论。 |
| 兴趣与生活方式 | 用长视频学习技术主题；常在写笔记和复习时回查讲解位置。 |
| 主要需求 | 把同一主题的少量课程视频放入笔记本，针对这些资料提问，并直接定位到支持回答的字幕。 |
| 次要需求 | 生成可核对的摘要与测验，保存自己的学习笔记。 |
| 核心痛点 | 长视频中重新寻找一个概念耗时；通用 AI 回答可能混入视频以外的信息；截图和文字笔记缺少时间定位。 |
| 代表场景 | 在两节课程视频中查找某概念的解释，阅读回答后逐条点击出处核对，再做小测验。 |

**需求推导：**问答范围必须限于用户选中的资料；每个有依据的结论应显示实际字幕及时间点；资料不足时要明确说明，不能补造出处。

### 1.3 画像三 何敏 下班后自学的职场学习者

| 项目 | 内容 |
| --- | --- |
| 基础信息 | 何敏，31 岁，市场运营专员，常住成都。 |
| 教育与技术水平 | 会安装桌面软件和打开视频，对 PocketBase、模型接口等配置概念不熟悉。 |
| 兴趣与生活方式 | 晚间用短时段观看培训录播；个人视频资料不愿上传公共平台。 |
| 主要需求 | 在本机保留视频，通过账号保存学习进度；中断或重启后继续复习和查看笔记。 |
| 次要需求 | 服务未配置、断网或视频文件移动时得到能理解的提示；能够重新关联本机文件。 |
| 核心痛点 | 配置门槛高；联网服务不稳定时不清楚学习记录是否保存；换电脑后原路径失效。 |
| 代表场景 | 晚上完成几张卡片后关闭应用，次日重新登录查看记录；移动视频后点击旧引用，按提示重新关联文件。 |

**需求推导：**要区分本机视频与账号学习数据的存放位置；远端写入失败不能显示成功；缺少本机文件时给出重新关联路径。

### 1.4 画像差异与范围

林悦以**词汇和听力记忆**为主，周航以**资料问答和出处核验**为主，何敏强调**短时使用、持久化和故障可理解性**。三人都使用自己合法取得的本机视频与字幕。首版不假设公开视频托管、跨设备自动同步整部视频或教师班级管理；这些能力不属于本次画像与故事的验收范围。

## 2 用户故事与验收标准

下表中的 P0 是期末演示主流程，P1 是稳定性与可用性，P2 是后续迭代。验收标准以可观察的界面、记录和视频位置为准，不把“感觉更好”当作通过条件。

### 2.1 账号与资料准备

**US01｜P0｜现有入口，待实机验证** 作为首次使用的个人学习者，我想创建并登录普通学习账号，以便我的词条、复习和笔记记录保存在自己的账号下。

- AC1：用有效信息注册并登录后，学习页显示当前账号状态；退出并重新登录后仍能读取该账号先前保存的记录。
- AC2：账号 A 创建的词条和笔记本，账号 B 的列表和直接读取请求均不能获得。

**US02｜P0｜现有入口，待实机验证** 作为已有本地生词的林悦，我想在首次登录时选择是否导入旧词，以便继续使用以前的学习积累。

- AC1：首次登录出现导入选择；选择不导入时，账号词表不增加，原本地词表仍在。
- AC2：选择导入后可查看导入结果；再次执行导入不会为同一词建立重复词条。

**US03｜P1｜现有入口，待实机验证** 作为重视隐私的何敏，我想明确知道视频文件存在哪里，以便决定是否使用账号功能。

- AC1：使用说明明确写出视频和字幕文件留在本机、PocketBase 保存学习记录与媒体标识。
- AC2：保存一条语境后，PocketBase 记录不包含本机视频的绝对路径，也不包含整部视频文件。

### 2.2 观看与语境收藏

**US04｜P0｜现有入口，待实机验证** 作为林悦，我想在观看时点击字幕查词并收藏，以便保留单词出现的真实语境。

- AC1：收藏后可在学习页看到词形、释义、字幕原句、视频标题和对应时间点。
- AC2：点击该语境的播放入口，打开正确视频并从对应字幕附近开始播放。

**US05｜P0｜现有入口，待实机验证** 作为林悦，我想在同一词再次出现时补充新语境，以便比较不同用法而不增加重复卡片。

- AC1：两次收藏同一词后，词条只有一条；不同字幕位置可分别查看。
- AC2：重复收藏同一视频的同一字幕行，不产生第二条完全相同的语境。

**US06｜P1｜现有入口，待实机验证** 作为周航，我想点击字幕时间点返回讲解位置，以便在阅读笔记时重新听原话。

- AC1：从学习页点击出处后，播放器加载目标视频并跳到保存的秒数附近。
- AC2：目标视频未在播放器中预先打开时，该跳转仍可完成。

### 2.3 复习与进度

**US07｜P0｜现有入口，待实机验证** 作为林悦，我想每天看到已经到期的生词，以便优先复习需要巩固的内容。

- AC1：到期卡片进入队列；未到期卡片不进入当日队列。
- AC2：完成一张卡片后，待复习数量随保存的作答结果更新；重启并重新登录后保持一致。

**US08｜P0｜现有入口，待实机验证** 作为林悦，我想先听原句并尝试回忆，再看到释义，以便检测自己是否真正记住。

- AC1：进入卡片时释义被遮盖；用户执行“显示答案”后才显示。
- AC2：有可用本机视频时可以播放该词所在的原声语境；缺少文件时提供明确提示。

**US09｜P0｜现有入口，待实机验证** 作为林悦，我想用“忘记、模糊、记得”评价本次回忆，以便系统安排下次复习。

- AC1：每次提交产生一条带词条、评分和时间的复习记录。
- AC2：三个评分按既定 FSRS 映射计算到期时间；同一组有序作答记录在重启后重建出同一到期结果。

**US10｜P1｜现有入口，待实机验证** 作为何敏，我想看到今日完成数和近期复习情况，以便决定今晚还要花多少时间。

- AC1：学习页显示待复习数、今日完成数和近七日“记得”比例，并说明统计口径。
- AC2：完成一条评分后刷新页面，数字与该账号的作答记录一致。

**US11｜P2｜迭代候选** 作为林悦，我想完成一次听句辨词练习，以便检验自己能否在原声中识别生词。

- AC1：播放原句时先不显示目标词；作答后显示正确词和原句。
- AC2：练习结果可单独查看，不会未经用户确认就改变正式复习排程。

### 2.4 视频学习笔记本

**US12｜P0｜现有入口，待实机验证** 作为周航，我想建立主题笔记本并选择已有视频，以便限定 AI 使用的资料。

- AC1：创建笔记本后可以添加带字幕的本机视频，并在资料列表看到标题。
- AC2：没有字幕的视频不能作为可问答资料；首版最多添加五个视频，超限时有明确提示。

**US13｜P0｜现有入口，AI 实答待验证** 作为周航，我想对笔记本中选定的视频提问，以便快速找到课程中对某个概念的解释。

- AC1：回答只引用当前笔记本资料；切换到未选中的视频内容时，不出现该视频的出处。
- AC2：回答中的每条可核对引用都能显示真实字幕文本、视频标题和时间点，点击后跳回对应片段。

**US14｜P0｜现有入口，AI 实答待验证** 作为周航，我想在资料不足时得到明确反馈，以便不把模型猜测当成课程内容。

- AC1：以与选定字幕无关的问题提问，界面明确表示资料不足或无法从资料确认。
- AC2：模型返回不存在的字幕编号时，系统不显示伪造引用，并提示回答无法核对。

**US15｜P1｜现有入口，AI 实答待验证** 作为周航，我想生成带出处的摘要，以便先了解视频要点再决定回看哪些部分。

- AC1：摘要仅基于当前笔记本选中的字幕资料。
- AC2：摘要的出处可显示视频、字幕和时间点；点击后定位到该处。

**US16｜P1｜现有入口，AI 实答待验证** 作为周航，我想根据笔记本资料完成小测验，以便检查对课程内容的理解。

- AC1：题目、正确答案与解释均可关联选定资料中的字幕出处。
- AC2：提交后能查看得分、自己的选择和正确答案；重新登录后仍能查看本次作答记录。

**US17｜P1｜现有入口，待实机验证** 作为周航，我想保存自己写的笔记，以便把 AI 内容与自己的理解放在一起对照。

- AC1：保存后重新打开笔记本，笔记正文仍在，并能辨别手写内容与 AI 生成内容。
- AC2：笔记引用的字幕出处在保存后仍可查看和点击核对。

### 2.5 故障与连续使用

**US18｜P1｜现有入口，待实机验证** 作为何敏，我想在网络中断时知道哪些记录没有保存，以便避免误以为学习进度已同步。

- AC1：断开 PocketBase 后提交复习或保存笔记，界面给出失败提示，不把失败操作计入已完成数。
- AC2：本机视频仍可播放；重新连接后可重新执行失败的学习操作。

**US19｜P1｜现有入口，待实机验证** 作为何敏，我想在视频移动或删除后得到重新关联提示，以便继续使用已保存的卡片和笔记出处。

- AC1：引用对应的本机文件不存在时，界面不静默失败，并说明需要重新关联。
- AC2：重新关联正确文件后，原有语境或出处可再次跳转到保存的时间点。

**US20｜P1｜现有入口，待实机验证** 作为何敏，我想切换账号时只看到当前账号的学习资料，以便与共用电脑上的其他人分开使用。

- AC1：退出 A 登录 B 后，学习页不残留 A 的词条、笔记本、统计或令牌。
- AC2：B 新增的记录不能在 A 的账号下读取；切回 A 后原有记录仍在。

### 3.2 平台智能体多轮对话提纲

课程指定在 [dire.muedu.org](https://dire.muedu.org) 的“学术协作 Native → 突触 AI 产品经理”开展真实多轮对话。当前文档未取得该平台的对话记录，以下为可直接使用的提问顺序；**不得把提纲当成已完成的交互证据**。

1. **画像挑战：**“CueLearn 面向本机带字幕视频的个人学习者。请分别质疑林悦、周航、何敏画像中不真实或过于宽泛的设定，并提出每人需要验证的两个问题。”
2. **痛点追问：**“对林悦的重复收藏和语境遗失、周航的 AI 引用可信度、何敏的断网与文件移动，各追问一次发生频率、损失和现有替代办法。”
3. **故事拆分：**“根据上述回答，把最重要需求写成‘作为角色，我想目标，以便收益’，指出目标和收益混写的故事，并给出可观察的验收标准。”
4. **反例检验：**“假设没有 AI 服务、PocketBase 断网或本机视频已移动，哪些故事会失败？请按 P0/P1 排序，并指出不应向用户承诺的能力。”
5. **结论对照：**“对比我们初稿的 US01 至 US20，列出建议采纳、暂缓和拒绝的意见及理由；不要假设用户访谈已完成。”

**平台交互证据待补：**对话日期＿＿；参与组员＿＿；会话链接或截图编号＿＿；关键原话/建议＿＿；我们采纳的改动及对应故事编号＿＿；未采纳意见与原因＿＿。

### 3.3 当前反思与核验清单

这份初稿由现有产品定位、开发文档和代码功能范围推导，尚未经过目标用户访谈、结对角色互换或课程平台智能体的真实交互核验。提交课程作业前，小组应完成上述两轮结对与平台多轮对话，把真实记录填入 3.1、3.2；若讨论改变了优先级或故事内容，应同步修改画像和 AC。尤其需要检验：林悦是否真的愿意每天复习、周航是否接受最多五个视频的限制、何敏能否独立完成 PocketBase 与 AI 配置。
