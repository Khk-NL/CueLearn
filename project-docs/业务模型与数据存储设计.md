# CueLearn 业务数据模型与「存什么」说明

> 主责：李（`app/models.py`）　日期：2026-10-20
> 对应课程《业务后端改造与数据采集交付》第 1 页要求：把 `Student` / `Enrollment` 换成本组业务模型，Create 与返回模型分开，**必须包含能用于学习分析的字段（如作答时长）**。

整合说明（2026-10-29）：已纳入main；当前模型还包括`DesktopCaptureCreate/Response`和`desktop_captures`收据表。严格类型和整数上限以`app/models.py`及[本轮交付报告](业务后端改造与数据采集交付报告.md)为准，以下字段表保留业务设计背景。

## 1. 一句话回答

CueLearn 存**四类业务事实**（生词、生词语境、复习作答、学习行为事件）和**一类派生统计**（用户学习概况）；所有记录都挂在匿名 `user_key` 上，不存真实姓名、账号凭据和本机文件路径。判断「存不存」的唯一标准是：**这条数据能不能让某个用户故事被验证、或者能不能被某条统计口径用到**——两者都不满足的，不存。

## 2. 从原型设计倒推「存什么」

数据不是为了「尽量多」而采集，而是倒推自《用户画像与用户故事》里已经写定的验收标准：

| 原型能力（用户故事 / 确认单） | 必须落库的事实 | 落到哪张表 | 不存会怎样 |
| --- | --- | --- | --- |
| 查词后一键收藏生词（B-2、C-1） | 单词、释义 | `vocabulary_items` | 卡片视图没有内容可渲染 |
| 生词要能跳回原视频核对（B-2「片段来源」、确认单「出处回跳」） | 字幕原句、媒体指纹、字幕序号、该句起始秒数 | `word_contexts` | 复习只剩「孤立单词」，退化成普通单词 App |
| 每次复习给出「忘记 / 模糊 / 记得」（确认单 `learning/review`） | 三档自评、作答时间、作答时长 | `review_events` | 到期数、今日完成数、记得比例全部算不出来 |
| 学习首页看投入与效果（确认单 `learning/overview`） | 上面的词条与复习记录聚合 | 不落表，查询时用 `LEFT JOIN` 现算 | 首页没有数据可展示 |
| 「听不懂到底是生词、连读还是语法」（画像 C 痛点 2）、提示与看翻译的频次 | 谁、何时、对什么、做了什么（含非评分动作） | `learning_events` | 只能看到「复习了几次」，看不到卡点在哪 |

结论：**存「能验证验收标准的最小事实集合」**，而不是把播放器状态、视频文件、账号资料一股脑搬进数据库。

## 3. 存储全景与本周边界

| 层 | 内容 | 实际位置 | 本周课程服务是否落库 |
| --- | --- | --- | --- |
| 本机媒体 | 视频文件、字幕文件、截取片段 | Electron 本机目录 | 否，只存媒体指纹 |
| 本机偏好 | 字幕模式、倍速、播放进度 | Electron 本地设置 | 否（属于 A-1、C-2 的「本地记忆」验收，不需要服务端） |
| 学习业务数据 | 生词、语境、复习作答 | PocketBase 集合 + 课程 SQLite 同构表 | 是 |
| 行为事件 | 查词、提示、看翻译、重播、收藏、复习提交 | `learning_events` | 是（对应确认单中「未接入」的 `events`） |
| 派生统计 | 词条数、复习次数、今日完成、记得比例、平均时长、到期数 | 查询结果，不落表 | 是（`LEFT JOIN` 报表） |
| 范围外 | 笔记本、资料、笔记、测验作答、完整 FSRS 排程 | 确认单的 `notebooks` / `notes` / `quiz_attempts` | 否，本周不实现也不伪造 |

## 4. 业务模型清单（`app/models.py`）

### 4.1 模型一览

| 模型 | 类型 | 用途 | 依赖表 |
| --- | --- | --- | --- |
| `WordContextCreate` / `WordContextResponse` | 提交 / 返回 | 一条字幕语境 | `word_contexts` |
| `VocabularyItemCreate` / `VocabularyItemResponse` | 提交 / 返回 | 生词及其全部语境 | `vocabulary_items` + `word_contexts` |
| `ReviewEventCreate` / `ReviewEventResponse` | 提交 / 返回 | 一次复习作答 | `review_events` |
| `ReviewEventList` | 返回 | 某匿名用户的复习记录 | `review_events` |
| `LearningEventCreate` / `LearningEventResponse` | 提交 / 返回 | 一条学习行为事件 | `learning_events` |
| `UserOverviewRow` / `OverviewReport` | 返回 | 报表一行 / 整张报表 | 上述四表聚合 |
| `RootResponse` / `HealthResponse` / `MessageResponse` | 返回 | 首页、健康检查、重置提示 | 无 |

### 4.2 字段表

**`vocabulary_items`（生词）**

| 字段 | 类型 | 必填 | 约束 / 单位 | 生成方 | 用途 |
| --- | --- | --- | --- | --- | --- |
| `user_key` | string | 是 | `^[A-Za-z0-9][A-Za-z0-9_-]{0,63}$`，≤64 字符 | 客户端 | 匿名归属，同一 `user_key` + `word` 唯一 |
| `word` | string | 是 | 1–80 字符，首尾去空格 | 客户端 | 词条本体 |
| `definition` | string | 是 | 1–500 字符 | 客户端 | 释义 |
| `created_at` | string | — | 服务端时间，精确到秒 | 服务端 | 第一次收藏时间 |

**`word_contexts`（语境）**

| 字段 | 类型 | 必填 | 约束 / 单位 | 用途 |
| --- | --- | --- | --- | --- |
| `sentence` | string | 是 | 1–1000 字符，去空格非空 | 字幕原句，复习时给语境 |
| `media_fingerprint` | string | 是 | 1–128 字符，**不得含 `/` 或 `\`** | 指回是哪部视频，替身「本机路径」 |
| `subtitle_index` | int | 是 | ≥0 | 第几条字幕 |
| `start_seconds` | float | 是 | ≥0，秒（可含小数） | 回跳定位 |

**`review_events`（复习作答）**

| 字段 | 类型 | 必填 | 约束 / 单位 | 生成方 | 用途 |
| --- | --- | --- | --- | --- | --- |
| `user_key` | string | 是 | 同上 | 客户端 | 谁 |
| `vocabulary_item_id` | int | 是 | **≥1**；必须是该 `user_key` 自己的词条，否则 404 | 客户端 | 复习哪个词 |
| `rating` | enum | 是 | `forgot` / `vague` / `remembered` | 客户端 | 三档自评 |
| `reviewed_at` | string | — | 服务端时间，精确到秒 | 服务端 | 何时（今日完成、近七日都靠它） |
| `duration_ms` | int | 否 | **≥0，单位毫秒** | 客户端 | 作答时长（学习分析字段） |

**`learning_events`（学习行为事件）**

| 字段 | 类型 | 必填 | 约束 / 单位 | 生成方 | 用途 |
| --- | --- | --- | --- | --- | --- |
| `user_key` | string | 是 | 同上 | 客户端 | 谁 |
| `event_type` | enum | 是 | `word_saved` / `word_lookup` / `review_submitted` / `hint_requested` / `translation_revealed` / `sentence_replayed` | 客户端 | 做了什么 |
| `target_type` | enum | 是 | `vocabulary_item` / `word_context` / `subtitle` / `media` | 客户端 | 对什么（类别） |
| `target_id` | string | 是 | 1–128 字符，**不得含 `/` 或 `\`** | 客户端 | 对什么（具体对象） |
| `payload` | string | 否 | 默认 `"{}"`，≤2000 字符，必须是 **JSON 对象文本**，且不含敏感键 | 客户端 | 非敏感附加上下文 |
| `created_at` | string | — | 服务端时间 | 服务端 | 何时 |

### 4.3 Create 与返回模型为什么必须分开

| 字段 | Create 是否要求客户端提交 | Response 是否返回 | 说明 |
| --- | --- | --- | --- |
| `id` | 否 | 是 | 自增主键，服务端生成 |
| `created_at` / `reviewed_at` | 否 | 是 | 服务端时钟，客户端无法伪造时间线 |
| `vocabulary_item_id`（语境里） | 否 | 是 | 由服务端在保存父词条后回填 |
| `contexts` | 是（至少 1 条） | 是 | 收藏生词必须带语境，否则「语境学习」不成立 |
| `rating` / `duration_ms` | 是 / 可选 | 是 | 业务事实 |

实测：客户端在请求体里塞 `"id": 999`、`"created_at": "2000-01-01T00:00:00"` 时，这两个值被忽略，落库仍是服务端生成的 `id` 与当前时间。

## 5. 学习分析字段：为什么是这几个

作业要求「必须包含能用于学习分析的字段」。本组选了下列字段，每个都能对应到一条统计口径或一条验收标准：

| 分析问题 | 依赖字段 | 统计口径 |
| --- | --- | --- |
| 今天复习了几次？ | `review_events.reviewed_at` | `substr(reviewed_at,1,10) = date('now','localtime')` 计数 |
| 近七日「记得」的比例高不高？ | `reviewed_at` + `rating` | 近 7 天内 `rating='remembered'` 的次数 ÷ 近 7 天总次数；无记录为 `null` 而非 0 |
| 复习一个词平均要花多久？ | `review_events.duration_ms` | `AVG(duration_ms)`，保留 1 位小数；全为 `null` 时为 `null` |
| 还有多少词该复习了？ | `rating` + `reviewed_at` | 取每个词最近一次评分，按固定间隔近似（见 11 节） |
| 收藏了多少词？ | `vocabulary_items` | 按 `user_key` 计数 |
| 用户到底在哪一步卡住？ | `learning_events` 四要素 + `payload` | 按 `event_type` 分组看查词 / 提示 / 看翻译 / 重播的分布 |

### 5.1 作答时长 `duration_ms` 的采集口径

- **单位**：毫秒，JSON 整数。不用秒，是因为一秒的粒度会把「2 秒想起」和「2.9 秒想起」压成同一个值，而复习作答的差异恰恰在这个尺度上。
- **起点与终点**：从复习卡片完整呈现（单词 + 语境可选）开始，到用户点击「忘记 / 模糊 / 记得」为止。不含页面加载与登录耗时。
- **`0` 与 `null` 的区别**：`0` 表示确实测到了「几乎瞬间作答」（例如误触连点），`null`（不传）表示**没有采集到**。两者不可互换——把没测到的写成 0 会把平均时长系统性拉低。
- **不做补造**：服务端只做校验（`≥0`）和保存，不猜时长、不用默认值填充。
- **取值边界**：独立复习接口使用严格非负整数并限制SQLite整数上限；桌面桥接限制JavaScript安全整数上限。数值合法不代表测量真实，平均值仍可能受异常样本影响。
- **职责边界**：时长的计时发生在桌面端，本服务不实现桌面计时，也不假装实现。

### 5.2 三档自评 `rating`

`forgot` / `vague` / `remembered` 对应确认单的「忘记 / 模糊 / 记得」。三档而非二档，是因为「模糊」能区分「完全想不起」与「勉强想起但没把握」，这两种情况对下次复习间隔的要求不同；也避免了逼用户在「会 / 不会」之间瞎选导致数据失真。注意：这是**自评**，不是客观测验正确率，报表里也不应标成「正确率」。

## 6. 不存什么（数据最小化）

| 不存 | 原因 | 替代做法 |
| --- | --- | --- |
| 真实姓名、邮箱、手机号、学号、身份证号 | 课程明确要求不采集；与学习分析无关 | 匿名 `user_key`，用正则把邮箱、中文姓名挡在 422 |
| 密码、令牌、API 密钥 | 本服务无鉴权，只在本机 `127.0.0.1` 演示 | 凭据留在 Electron 主进程，不进课程库 |
| 本机视频绝对路径 | 换设备即失效，且泄露个人目录结构 | `media_fingerprint`；模型层拒绝含 `/`、`\` 的值 |
| 视频、字幕、音频文件本体 | 体积大、涉及版权与隐私 | 只存指纹、序号、秒数；文件留在本机 |
| 设备指纹、IP、地理位置 | 与学习分析无关 | 不采集 |
| `payload` 里的 `name` / `email` / `password` 等键 | 防止敏感信息借事件表绕过校验进来 | 递归检查键名，命中即 422 |

`user_key` 的设计是「匿名但可聚合」：同一个 `user_key` 的多次复习能被连成一条学习曲线，但它本身推导不出任何真实身份。

## 7. 与《开发方案确认单》PocketBase 集合的对应

| 课程 SQLite 表 | 对应模型 | 确认单集合 | 字段差异说明 |
| --- | --- | --- | --- |
| `users` | `user_key` 字段 | `users` | 确认单里是登录账号；课程服务只保留匿名键，不存账号认证信息 |
| `vocabulary_items` | `VocabularyItemCreate/Response` | `vocabulary_items` | 字段同义（`word` / `definition`） |
| `word_contexts` | `WordContextCreate/Response` | `word_contexts` | `media_fingerprint` 对应确认单「视频指纹」，不上传路径 |
| `review_events` | `ReviewEventCreate/Response` | `review_events` | 确认单 JSON 示例 `{"owner","word_item","rating","reviewed_at"}` 对应 `user_key`、`vocabulary_item_id`、`rating`、`reviewed_at`；课程版多出 `duration_ms`，正是作业要求的学习分析字段 |
| `learning_events` | `LearningEventCreate/Response` | `events`（确认单标注「尚未接入」） | 本服务把它实现为独立事件表，四要素齐全 |
| 无 | — | `notebooks` / `notebook_sources` / `notes` / `quiz_attempts` | 属其余组员范围，本周不建表、不写死字段 |

两套存储共享同一组字段名，桌面端把一次复习转发到 `POST /events` 时不需要做字段映射。

## 9. 无效数据与 422 示例（实测，逐条来自模型校验）

| 场景 | 请求体关键字段 | 状态码 | 返回的 `detail`（摘要） |
| --- | --- | --- | --- |
| 缺词条字段 | 无 `word`，`contexts: []` | 422 | `word: Field required`；`contexts: List should have at least 1 item` |
| `contexts` 为空 | `"contexts": []` | 422 | `contexts: at least 1 item ... not 0` |
| `user_key` 是邮箱 | `"lizhangtao@stu.edu.cn"` | 422 | `String should match pattern '^[A-Za-z0-9][A-Za-z0-9_-]{0,63}$'` |
| `user_key` 是中文姓名 | `"李章韬"` | 422 | 同上（姓名进不来） |
| 媒体指纹是本机路径 | `"D:/videos/a.mp4"` | 422 | `媒体指纹不能是本机文件路径` |
| 评分不在三档内 | `"rating": "easy"` | 422 | `Input should be 'forgot', 'vague' or 'remembered'` |
| 作答时长为负 | `"duration_ms": -1` | 422 | `Input should be greater than or equal to 0` |
| 词条 id 为 0 | `"vocabulary_item_id": 0` | 422 | `Input should be greater than or equal to 1` |
| 事件类型未知 | `"event_type": "page_view"` | 422 | `Input should be 'word_saved', ... or 'sentence_replayed'` |
| `payload` 不是 JSON | `"payload": "not-json"` | 422 | `payload 必须是 JSON 文本` |
| `payload` 含敏感键 | `{"email":"..."}` | 422 | `payload 不得包含姓名、邮箱、密码等敏感字段` |
| 对象标识是本机路径 | `"target_id": "D:/videos/lecture.mp4"` | 422 | `对象标识不能是本机文件路径，请改传媒体指纹或业务 id` |
| 词条不存在 | `"vocabulary_item_id": 999` | **404** | `词条 999 不存在` |

**422 与 404 的分界线**：字段本身不成立（类型、取值、格式、互斥关系）是 422；字段格式完全合法、但数据库里找不到对应记录才是 404。所以 `vocabulary_item_id = 0` 是 422（自增主键从 1 开始，0 不可能是真实词条），而 `999` 是 404。

## 11. 已知限制

1. **区分上报入口**：独立 `/events` 没有幂等键；桌面 `/desktop/captures` 已通过独立收据表实现同事件去重、冲突409和事务回滚，不应将两个接口混为一谈。
2. **`duration_ms` 由客户端上报**：服务端无法验证真实计时，只能约束取值范围。桌面已接入可见计时与桥接；本轮验收采用合成时长，不作为实际学习行为数据。
3. **到期数是固定间隔近似**，不是 FSRS：忘记立即到期、模糊 1 天后、记得 3 天后。正式排程按 `review_events` 历史推导（郑）。
4. **`payload` 是 JSON 文本而非结构化列**：便于扩展，但做分析查询时需要在 SQL 里二次解析（SQLite 的 `json_extract`）。
5. **本服务无鉴权**，`user_key` 不是凭据，只适合本机演示；`DELETE /admin/reset` 仅限本地。
6. **笔记本、笔记、测验作答未纳入**：确认单里的 `notebooks` / `notes` / `quiz_attempts` 不在本周范围，本文不为其设计字段，避免做成「看起来设计过、其实没有实现」的假模型。
