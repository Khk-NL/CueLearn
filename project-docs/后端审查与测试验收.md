## 已发现并修复的问题

| 问题 | 影响 | 修复与验证 |
| --- | --- | --- |
| 测试直接调用默认库的 `reset_db()` | 执行 pytest 会清空根目录演示数据 | 每个测试在 `tmp_path` 建独立库；进入 `with TestClient(app)` 执行真实 lifespan，重置接口也只操作临时库 |
| 词条 ID、字幕序号和时长缺少严格整数或 SQLite 上界 | 布尔值、字符串、小数可能被转换，超大整数触发500 | 模型校验整数类型及64位范围；查询路径也验证范围；非法请求422且不写库 |
| 非有限字幕时间被接受 | 数据库写入无穷大，响应时间却变成null | 字幕秒数要求有限且非负；原始 `1e309` 请求稳定返回422 |
| 422详情包含不可序列化的原始输入 | 已被模型拒绝的无穷数值仍可能在错误处理时触发500 | 验证错误仅返回 `type`、`loc`、`msg`，保留字段与原因，不回显原始输入 |
| 创建模型静默忽略未声明字段，事件敏感键不完整 | 错填字段或传入凭据时不能明确拒绝 | 四个创建模型拒绝额外字段；嵌套对象与数组中的令牌、密钥等敏感键返回422 |
| SQLite事务退出后没有明确关闭连接 | Windows下数据库文件可能依赖垃圾回收才能释放 | 上下文管理器在提交、回滚或初始化异常后关闭连接；用真实连接验证关闭与回滚 |
| 重试相同收藏会追加完全相同的语境 | 同一语境重复展示 | 在现有事务中以参数化SQL判断完全相同语境，只增加新语境；不改表、不删除既有记录 |
| 文档仍描述已被替换的 `/learners`、UUID等协议 | 启动、参数与验收方法和当前代码不符 | 更新为实际下划线路径、根目录 `learn.db`、当前评分与统计口径 |

SQL外部值使用 `?` 参数；复习写入核对词条与提交匿名标识的对应关系；词条和复习分别聚合后 `LEFT JOIN`，没有发现统计乘积放大。事件存储读取函数由测试直接验证，不新增接口来充当既有功能。

复现命令：

```powershell
uv sync --locked
uv run --locked pytest -v
```

本轮实际命令额外写入被忽略的 JUnit 证据：

```powershell
.\.local\course-tools\bin\uv.exe run --locked pytest -v --junitxml=.local/course-pytest-20261022.xml
```

**结果：84 passed in 3.91s；0失败、0跳过、0警告。** 原有22项用例保留，增加参数化与集成回归验证。测试前后根目录 `learn.db` 均不存在，没有创建、读取或清空真实演示数据库。
