## 2. 事件表结构（`learning_events`）

| 字段 | 含义 | 示例 |
| --- | --- | --- |
| `user_key` | 谁（匿名标识，非姓名） | `anon-listener` |
| `created_at` | 什么时候（服务端写入） | `2026-10-20T14:34:32` |
| `target_type` + `target_id` | 对什么 | `subtitle` / `sha256-demo:1` |
| `event_type` | 做了什么 | `hint_requested` |
| `payload` | 非敏感附加上下文（JSON 文本） | `{"level":"syntax"}` |

明确不采集：真实姓名、邮箱、密码、手机号、学号、设备指纹、本机视频路径。

`POST /events` 示例：

```json
{
  "user_key": "anon-listener",
  "event_type": "hint_requested",
  "target_type": "subtitle",
  "target_id": "sha256-demo:1",
  "payload": "{\"level\":\"syntax\"}"
}
```

成功返回 `201`，并带上服务端生成的 `id`、`created_at`。

## 3. 报表 SQL 要点（LEFT JOIN）

左表为完整用户范围 `users`，再分别聚合词条与复习后 **LEFT JOIN**：

- 只上报过行为、从未复习的人 → 复习次数为 `0`，记得比例 / 平均时长为 `null`，**行仍出现**
- 只收藏未复习的人 → 同上，且 `due_count ≥ 1`
- 若用 `INNER JOIN`，上述用户会被漏掉（课程明确禁止）

实现见 `app/storage.py` 中 `report_overview()`。

## 4. 演示数据与统计结果（2026-10-20 实测）

为验收构造四类匿名用户后调用 `GET /reports/overview`：

| 匿名用户 | 角色说明 | 词条数 | 复习次数 | 今日完成 | 近七日记得比例 | 平均时长 ms | 到期数 |
| --- | --- | ---: | ---: | ---: | --- | --- | ---: |
| `anon-kept` | 收藏并复习（记得） | 1 | 1 | 1 | 1.0 | 800 | 0 |
| `anon-listener` | **仅上报行为，未收藏未复习** | 0 | 0 | 0 | null | null | 0 |
| `anon-mixed` | 同一词记得一次、忘记一次 | 1 | 2 | 2 | 0.5 | 2000 | 1 |
| `anon-pending` | **只收藏，从未复习** | 1 | 0 | 0 | null | null | 1 |

要点：`anon-listener` 与 `anon-pending` 因 LEFT JOIN 出现在报表中，不会被「没复习」过滤掉。
