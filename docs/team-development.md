# CueLearn 小组协作开发指南

本文供梁、郑、严、李、肖五位组员协作使用。产品范围和当前实现见[产品定位](product-positioning.md)与[课程学习开发说明](course-learning.md)；代码约定以仓库根目录的 [AGENTS.md](../AGENTS.md) 为准。

## 1. 分支与合并

`main` 保存已集成、可供其他组员继续开发的版本。**日常改动先从最新 `main` 建自己的分支，再发起指向 `main` 的 Pull Request（PR）**。不要在多人共用的 `main` 上同时直接开发，也不要继续把 `codex/campus-learning` 当作协作分支。

分支名说明工作内容即可，例如 `feat/review-card`、`fix/subtitle-jump`、`docs/demo-guide`。一个分支尽量完成一件事；涉及播放器和笔记本等不同模块时，先拆成可独立检查的改动。紧急的小修正若需要直接进入 `main`，也应先告知组员、完成针对性检查，并避免与正在进行的分支编辑同一片代码。

开始工作：

```bash
git switch main
git pull --ff-only origin main
git switch -c feat/your-feature
```

完成修改后，先检查 `git status` 和差异，只提交本次任务的文件。提交信息按仓库约定使用 `feat:`、`fix:`、`docs:` 等前缀；不要提交视频、字幕、PocketBase 数据目录、生成文件、密钥或本机配置。推送自己的分支后，在 GitHub 上向 `main` 提 PR：

```bash
git add -p
git commit -m "feat: describe the change"
git push -u origin feat/your-feature
```

PR 说明至少写清：改了什么、为什么改、怎样验证、尚未验证什么。界面流程变化附截图；涉及数据迁移、首次资源下载或配置步骤的变化，写明组员更新本地环境时要做什么。请另一位组员查看主要流程与差异后再合并。合并后，下一项工作从更新后的 `main` 新建分支，不在已合并分支继续累积无关功能。

如果开发期间 `main` 已更新，先提交或妥善保存自己的修改，再运行 `git fetch origin`、`git merge origin/main`，解决冲突并重新检查受影响功能。不要用强制推送覆盖别人共用的分支。发生冲突时，核对双方意图；播放器、学习服务和 README 的冲突尤其需要同时保留有效功能、来源署名与配置说明。

## 2. 代码位置与职责

| 工作 | 主要位置 | 协作提醒 |
| --- | --- | --- |
| 播放、字幕、时间跳转 | `src/fronted/features/player/`、`src/backend/services/WatchHistoryService.ts` | 保留原有本地播放和字幕行为，新增学习入口时检查从出处返回播放器。 |
| 学习页面与复习卡片 | `src/fronted/features/learning/` | 用户文案同时更新 `src/fronted/i18n/locales/zh-CN/` 与 `en-US/`。 |
| 生词、FSRS、笔记本业务 | `src/backend/services/LearningService.ts`、`src/backend/services/learning/` | 从主进程访问 PocketBase；复习作答记录是排程事实来源。 |
| PocketBase 与本机媒体映射 | `src/backend/infrastructure/learning/`、`pb_migrations/` | 用户数据按账号隔离；视频留本机，服务端只存媒体标识和必要出处。 |
| IPC 契约 | `src/backend/controllers/LearningController.ts`、`src/common/api/api-def.ts` | 新业务调用同时更新契约、主进程路由和前端 API。 |
| 运行与开源说明 | `README.md`、`docs/`、`OPEN_SOURCE_USAGE.md` | 功能状态以实际代码和验证为准；保留上游及第三方版权许可信息。 |

沿用 React 界面 → Electron IPC → 主进程服务 → 本地文件或 PocketBase 的分层。新增功能前先找现有播放、字幕解析、AI 配置、并发控制和翻译能力，能复用就不要再建一套。不要把 PocketBase 令牌、视频绝对路径或服务密钥传给渲染进程或提交到仓库。更详细的文件摆放规则见[架构指南](architecture-guidelines.md)。

## 3. 本机启动与共同配置

使用项目 `package.json` 约定的 Node.js 22 和 Yarn 1。安装依赖后运行 `yarn start`。Windows 下运行仓库根目录的 `start-pocketbase.cmd` 启动 PocketBase；它会选择空闲端口，组员应把脚本显示的地址填入应用「语境学习」页。首次启动会应用 `pb_migrations/`，不要把本机 `pb_data/` 推送到仓库。

每人使用自己的普通学习账号测试。PocketBase 管理后台账号不用于应用登录。AI 问答和测验需要个人在应用「设置 → 服务与资源」填写可用服务；远程 PocketBase 与 AI 接口由组长统一确定后再配置，不能把地址、密钥或真实用户数据写进代码、截图和 PR。没有 AI 服务时，可先检查资料选择、字幕读取及错误提示，并在 PR 中注明真实回答尚未验证。

## 4. 提交前检查

先做与改动直接相关的验证，再按需运行完整检查：

```bash
node_modules/.bin/tsc --noEmit
yarn lint
yarn test:run
```

Windows 可使用 `node_modules\.bin\tsc.cmd --noEmit`。完整 lint 和测试目前存在已记录的既有失败；PR 中写出本次运行的实际结果，不能把“未新增失败”写成“全部通过”。测试约定见[测试指南](testing-guidelines.md)，桌面端完整流程见[e2e 指南](e2e-testing.md)。课程验收重点是“观看 → 收藏 → 复习 → 笔记本问答 → 点击出处回跳”，并检查账号切换、重复收藏、断网和本机文件缺失时的行为。

每次更新对外功能，同步修改对应文档。只把亲自运行并看到结果的步骤列为“已验证”；远程服务尚未配置时明确写“待验证”。

## 5. 分工与同步

当前分工见[开发方案确认单](../project-docs/开发方案确认单.md)。各模块负责人可以在自己的分支独立实现，但共用的 IPC 契约、数据库集合和导航入口应尽早在 PR 说明里告知其他组员。每周同步进度时核对：正在做的分支、待评审 PR、可演示流程、阻碍与下一步负责人。

GitHub 是当前开发仓库。Gitee 地址尚未提供；创建后再记录实际远程地址和同步办法，不猜测目标。期末提交材料应与 `main` 的代码和验证记录保持一致。

## 6. 六周任务安排

以开始协作的那一周为第 1 周，每周为一个阶段。现有账号、复习和笔记本代码已接入，因此表中的“完成”指核对现状、修正问题并拿出可演示、可验证的结果，不要求重写已有功能。各人从最新 `main` 创建自己的分支；需要改共用接口或集合时，先在周会上对齐字段和负责人。

### 第 1 周：建立共同基线

| 成员 | 当周工作与交付 |
| --- | --- |
| 梁（组长） | 核对需求、现有实现和课程验收项；分配模块边界，记录本机启动、PocketBase 迁移及当前测试结果；建立 PR 和周会记录模板。交付一份问题清单和验收清单。 |
| 郑 | 检查三档评分到 FSRS 排程、到期队列和统计的数据流；记录固定评分序列的预期结果。交付复习模块检查清单。 |
| 严 | 检查打开文件夹、播放、字幕显示、时间跳转以及学习页返回播放器的路径。交付两段带字幕的可复现演示流程。 |
| 李 | 检查查词、收藏、取消收藏、重复收藏及旧生词导入的界面流程。交付单词卡和收藏流程的问题清单。 |
| 肖 | 检查笔记本资料选择、问答、摘要、测验与引用定位的现状。交付两段视频的资料与引用检查清单。 |

**周会对齐：** 确认课程范围、五人分工、可演示基线、阻碍及第 2 周 PR；把“已实现”和“待验证”分开记录。

### 第 2 周：账号与数据边界

| 成员 | 当周工作与交付 |
| --- | --- |
| 梁（组长） | 用本机 PocketBase 检查集合迁移、普通账号登录、两个账号的数据隔离、重启后重新登录及网络错误提示；修正发现的后端问题。交付账号与集合规则的验证记录。 |
| 郑 | 核对复习事件只属于当前账号，账号切换后到期数和统计不会串号；与梁确认事件字段。交付跨账号复习检查结果。 |
| 严 | 核对视频文件只留本机、媒体指纹与路径映射可重新关联；检查缺失文件提示。交付本机媒体边界检查结果。 |
| 李 | 核对首次导入需用户确认、本地旧词保留、重复词条不会重复创建；检查大量旧词导入时的界面反馈。交付导入与收藏验证记录。 |
| 肖 | 核对笔记本、资料、笔记和测验的账号归属；检查退出及切换账号后页面不会显示前一账号内容。交付笔记本隔离检查结果。 |

**周会对齐：** 现场用两个普通账号演示隔离；确认集合或 IPC 字段变更是否影响其他模块。

### 第 3 周：语境生词复习闭环

| 成员 | 当周工作与交付 |
| --- | --- |
| 梁（组长） | 联调“字幕查词 → 收藏 → 复习 → 重启后查看记录”，审查相关 PR 和 PocketBase 写入结果。交付闭环验收记录。 |
| 郑 | 验证忘记、模糊、记得的排程、短期到期刷新和近七日统计；修正算法或统计偏差。交付可复现的评分序列及结果。 |
| 严 | 检查复习卡的原句、原声或视频片段入口能回到正确视频和时间；修正媒体回跳问题。交付回跳核对记录。 |
| 李 | 完成单词卡、揭示释义、评分操作及收藏反馈的可用性修正；检查大量词条时仍可操作。交付界面截图和操作记录。 |
| 肖 | 核对收藏的字幕原句、视频标题和时间点在笔记本资料中可辨认；向严、李反馈跨模块引用问题。交付语境出处抽查结果。 |

**周会对齐：** 每人用同一段字幕演示自己的环节；确认重复收藏、文件缺失和离线时的提示。

### 第 4 周：视频学习笔记本闭环

| 成员 | 当周工作与交付 |
| --- | --- |
| 梁（组长） | 核对 AI 配置入口、主进程调用和资料权限边界；未配置真实 AI 服务时记录无法验证的部分。交付笔记本联调记录。 |
| 郑 | 检查笔记本测验作答持久化和学习首页统计是否各自基于正确数据，避免把未采集事件算入统计。交付数据口径说明。 |
| 严 | 联调字幕引用点击后打开正确本机视频、跳到正确时间；检查视频或字幕变化后的提示。交付引用回跳抽查表。 |
| 李 | 检查从播放器进入笔记本及从笔记本回到视频的操作路径和文案；协助修正学习页的导航与空状态。交付界面检查结果。 |
| 肖 | 验证资料选择上限、添加和移除资料、问答、摘要、笔记、测验及出处对应；修正资料不足、无效引用等问题。交付两段字幕的问答与引用核对记录。 |

**周会对齐：** 用两段带字幕的视频演示资料选择、提问、引用回跳和测验；真实 AI 服务未配置时，只验收能够实际运行的部分。

### 第 5 周：集成、异常场景与协作复核

| 成员 | 当周工作与交付 |
| --- | --- |
| 梁（组长） | 合并已通过评审的 PR，核对账号切换、断网、本机视频丢失时的整体行为；组织完整 lint、测试和构建，归档实际结果。 |
| 郑 | 复核大量生词下的队列性能、排程结果和统计口径；修正由集成带来的回归。交付复习回归结果。 |
| 严 | 复核文件夹视频列表、字幕播放、原声片段和引用回跳；在另一台组员电脑上核对本机文件重新关联。交付播放回归结果。 |
| 李 | 复核收藏、取消收藏、首次导入、重复收藏与错误反馈；检查中英文界面文字。交付单词流程回归结果。 |
| 肖 | 复核笔记本资料不足、字幕变化、AI 服务不可用与测验保存；检查引用文本、视频和时间点一致。交付笔记本回归结果。 |

**周会对齐：** 逐条过问题清单、测试失败和 PR；为每个未解决问题指定负责人、复现步骤与完成期限。

### 第 6 周：期末交付与演示

| 成员 | 当周工作与交付 |
| --- | --- |
| 梁（组长） | 核对 `main`、README、确认单、开源使用说明和实际验证结果；组织最终演示。取得 Gitee 实际地址后再配置并核对同步，按课程要求确认教师成员。交付仓库与验收材料清单。 |
| 郑 | 准备三档评分与学习统计的演示数据，说明 FSRS 排程依据；交付该部分演示步骤和答疑要点。 |
| 严 | 准备带字幕的视频及本机文件映射，演示原声、字幕与出处回跳；交付播放部分演示步骤。 |
| 李 | 准备查词、收藏、导入和单词卡的演示路径，核对空状态及用户提示；交付词汇部分演示步骤。 |
| 肖 | 准备两段视频的笔记本、问答、引用与测验演示；真实 AI 服务可用时核对回答质量，不可用时如实标注。交付笔记本部分演示步骤。 |

**周会对齐：** 全员按“观看 → 收藏 → 复习 → 笔记本问答 → 点击出处回跳”走一次完整彩排；核对提交材料与 `main` 一致，记录仍受外部服务配置影响的项目。

每次周会由梁记录结论：上周任务的实际完成证据、本周合入的 PR、未通过的验证、阻碍、下周负责人和完成日期。会议结束后把记录放在小组共同使用的位置，并在相关 PR 或文档中更新决定；没有运行过的流程不能写成已验收。
